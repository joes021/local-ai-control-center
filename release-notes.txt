v2.24.22
========

- Windows installer no longer blocks on a synchronous runtime start, so setup can reach Finish instead of hanging after model bootstrap.
- Windows OpenCode launch now chooses direct interactive launch when the backend already runs in the logged-in desktop session, and only falls back to scheduled-task launch from Session 0 style contexts.
- Fresh Windows install seeds lower-RAM startup settings for small GPU classes so OpenCode does not immediately inherit the overly strict 1024 output-token cap.

v2.24.20
========

- Fresh installer rebuild from the current stable Windows and Linux runtime state.
- GitHub release republished so latest setup assets match the live-tested portal/runtime behavior from 2.24.19.

v2.24.19
========

- `Open OpenCode` iz web portala na Windowsu sada koristi interaktivni scheduled-task launch, pa novi OpenCode prozor izlazi u korisnicku desktop sesiju umesto u Session 0.
- `Home` i `OpenCode` stranice sada periodično osvežavaju status, pa portal vise ne ostaje zalepljen na starom `offline` / `Nedostupan` stanju kada su runtime i OpenCode vec zdravi.
- `Run llama.cpp web` iz portala sada otvara lokalni web URL direktno iz browser klika, umesto da zavisi samo od server-side Windows `Start-Process` toka.

v2.24.18
========

- Windows installer i instalirani launcher payload sada ispravno prepoznaju `apps\llama.cpp\bin\llama-server.exe`, pa runtime vise ne ostaje “offline” odmah posle instalacije.
- Windows OpenCode launch spec sada ume da koristi `opencode.ps1` i `opencode.exe` iz modernog npm layout-a, pa `Open OpenCode` iz portala vise ne ostaje nedostupan dok precica radi.
- Windows runtime/status backend sada koristi pravi Windows process listing umesto Linux `ps -ef` fallback-a, pa portal ispravno prikazuje zdrav runtime i aktivan binar.

v2.24.17

- Time setup stvarno stize do payload copy, desktop shortcut faze i folder ikonice, umesto da se prekine prerano i ostavi polu-instaliran root bez `.lnk` fajlova.

v2.24.14
========

- Browser download status i pending rezultat vise nisu zakucani skroz ispod tabele, nego stoje odmah ispod detail panela uz model na koji se akcija odnosi.
- Browser download status sada ima i pravi progress bar, pa se ETA/procenat vizuelno vide odmah posle klika na `Download`.
- Benchmark grafikon sada koristi objedinjeni signal iz `history` i `liveHistory`, pa vise ne ostaje prazan kada pokrenes klasicni benchmark test.
- Dodat je `Clear benchmark values` tok koji resetuje benchmark metrike, live istoriju i sacuvane benchmark run vrednosti pre novog merenja.
- Updates fallback sada cita latest release direktno sa `joes021/local-ai-control-center` GitHub release API-ja, sa ispravnim Windows, Ubuntu x86_64 i Ubuntu arm64 installer URL-ovima.
- Update installer nazivi i putanje vise nisu legacy `Local-Qwen-Setup-*`, nego prate stvarne `Local-AI-Control-Center-*` release artefakte.
- Fixed Hugging Face browser size detection by preserving repo slashes in tree API requests, so Browser table sizes now load instead of staying `Unknown`.
- Fixed detected active local models outside the managed models folder so they appear as installed and active in the Models tab.
- Fixed Linux installer payload to package the real legacy Linux launchers plus `install/shared`, and to copy shared `config/` and `scripts/` into the install root so Browser downloads, model activation, and OpenCode launchers work on Ubuntu installs.
- Tightened Linux runtime readiness reporting when an already healthy runtime port is reused during install.
- Fixed Linux launcher patching so Browser `Download` no longer writes a broken OpenCode `baseURL` expression.
- Fixed Linux TUI installer so model selection writes a clean `selectedModelId` instead of capturing the visible menu text.
- Added Linux fallback activation for detected local GGUF models that exist outside the managed models directory, so portal model switching can recover those real local files too.
